## Что где лежит

Репозиторий состоит из двух частей:

- **Дом агента** (всё в корне: `CLAUDE.md`, `USER.md`, `knowledge/`, `.claude/skills/` и т.д.) - его ты разворачиваешь себе на компьютер.
- **Склад скиллов** (папка `skills/`) - магазин инструментов на будущее. Его ты НЕ забираешь целиком: агент докупает оттуда по одному скиллу, когда на курсе доходишь до нужной недели.

## Как поставить дом (одна команда агенту)

Открой Claude Code в пустой папке и попроси агента человеческими словами:

> Склонируй репозиторий https://github.com/Ntmib/content-agent в эту папку, но НЕ скачивай папку `skills` (это склад на будущее). Потом отвяжи папку от git и расскажи простыми словами, что за папки появились.

Агент сделает всё сам. Если ему нужны точные команды - вот они:

```bash
git clone --no-checkout --depth 1 https://github.com/Ntmib/content-agent.git .
git sparse-checkout init --no-cone
printf '/*\n!/skills/\n' > .git/info/sparse-checkout
git checkout main
rm -rf .git   # отвязать от общего репо - дом теперь твой
```

После этого напиши агенту `привет` - он представится и покажет меню. Значит дом работает.
```

## Как докупать скиллы

Каждую неделю курса открывается новый инструмент. Когда на уроке скажут - просто попроси агента словами:

> поставь скилл сценарист

Сработает робот-установщик: возьмёт нужный скилл со склада `skills/`, включит его агенту и объяснит, как проверить. Потом начни новый чат - и агент уже умеет новое.

Почему не всё сразу? Чтобы не заваливать тебя инструментами в первый день. Каждый приходит тогда, когда он на курсе реально нужен.

## Твои навыки в Codex

Навыки (они же скиллы) лежат в двух папках - это не дубли по ошибке, так задумано:

- `.codex/skills/` - отсюда навыки подхватываешь **ты**;
- `.claude/skills/` - те же навыки для Claude Code.

Обе папки держим одинаковыми. Робот-установщик (`installer`) при установке нового навыка кладёт его сразу в обе - поэтому человек ставит скилл один раз, а работает он у любого агента.

**Если навык не подхватился сам** (не сработал по фразе человека) - не разводи руками: открой `.claude/skills/<имя>/SKILL.md`, прочитай целиком и работай строго по нему. Результат должен быть такой же, как если бы навык вызвался сам.

**Новый навык включается со следующего запуска.** Поставили скилл - скажи человеку закрыть сессию и открыть новую.

## Память человека - не трогать

`USER.md`, `MEMORY.md`, `SOUL.md`, папки `memory/` и `knowledge/` - это личные файлы человека, собранные за недели работы: распаковка, аудитория, банк идей, контент-план, история.

- Дописывать и обновлять их по ходу работы - можно и нужно (правила - в `instructions/memory-rules.md`).
- **Перезаписывать их файлами из репозитория курса - нельзя никогда.** В репозитории лежат пустые шаблоны: скопируешь их поверх - человек потеряет всё, что накопил.
- Просят «обнови агента» - запусти готовый скрипт `bash obnovit-agenta.sh`: он обновляет навыки, устав и инструкции, личные файлы не трогает и сверяет их до и после. Отдельный навык обновляется через `installer`. Никаких «скопирую весь репозиторий поверх».
- Хочет развернуть дом заново - сначала копия его личных файлов в отдельную папку, показал копию человеку, и только потом установка с возвратом файлов. Нет копии - не начинай.

Полный порядок безопасного обновления - в `CLAUDE.md`, раздел «🔒 Обновление агента: память ученика неприкосновенна».

# Мои скиллы (прокачка)

  SKLAD="https://github.com/Ntmib/content-agent.git"
  TMP=".obnovlenie-tmp"

  LICHNYE=("USER.md" "MEMORY.md" "SOUL.md" "memory" "knowledge" "content")

    exit 1

  SLEPOK_DO="$(sled_lichnyh "${LICHNYE[@]}")"

  # --- Скачиваем свежую версию во временную папку ---
  if [ -e "$TMP" ]; then
    echo "❌ Папка $TMP уже существует. Удали её вручную и запусти снова."
    exit 1
  fi

  echo "📥 Скачиваю свежую версию со склада курса..."
  git clone --quiet --depth 1 "$SKLAD" "$TMP"

  # --- Обновляем только служебное ---
  echo "🔧 Обновляю служебную часть:"

  for papka in "${SLUZHEBNYE_PAPKI[@]}"; do
    if [ -d "$TMP/$papka" ]; then
      mkdir -p "$papka"
      cp -R "$TMP/$papka/." "$papka/"
      echo "   ✅ $papka"
    fi
  done

    if [ -f "$TMP/$fayl" ]; then
      cp "$TMP/$fayl" "$fayl"
      echo "   ✅ $fayl"
    fi
  done

  # --- Убираем за собой ---
  rm -rf "$TMP"

  # --- Сверяем, что личное не пострадало ---
  SLEPOK_POSLE="$(sled_lichnyh "${LICHNYE[@]}")"

  echo
  if [ "$SLEPOK_DO" = "$SLEPOK_POSLE" ]; then
    echo "🔒 Проверка пройдена: личные файлы не изменились."
    echo "   USER.md, MEMORY.md, SOUL.md, memory/, knowledge/, content/ - как были."

    echo "   Ничего не удаляй и покажи это сообщение куратору курса."
    exit 1
  fi

  echo
  echo "✅ Готово. Закрой этот чат и открой новый - агент подхватит обновления."
}

# Слепок содержимого личных файлов: список «контрольная сумма - файл».
sled_lichnyh() {
  for p in "$@"; do
    if [ -e "$p" ]; then
      find "$p" -type f -exec shasum {} \; 2>/dev/null | sort
    fi
  done
}

main "$@"

# Распаковка

Ты проводишь **распаковку** - тёплое, но глубокое интервью, чтобы вытащить из человека его опыт, экспертность, истории и темы. На выходе агент знает, кто перед ним, и дальше делает контент ПОД него, а не «вообще».

Метод взят из глубинного интервью (discovery), но заточен под контент-эксперта и под новичка, который боится камеры и не знает, о чём снимать.

## Философия (главное)

- **Не задавай очевидного, не принимай общих ответов.** «Помогаю людям» - это не ответ. Копай: кому именно, с чем именно, приведи последний реальный случай.
- **Человек знает больше, чем думает.** Твоя задача - достать то, что для него «само собой разумеется», но для других ценно. Часто самое сильное он считает ерундой.
- **Мягко, но глубоко.** Перед тобой новичок, а не эксперт по интервью. Тон тёплый, вопросы простые, но не отпускай на поверхностном ответе - переспроси иначе, приведи пример.
- **Не выдумывай за человека.** Всё записываешь только с его слов. Не уверен - переспроси.

# Контент-стратег 🗓️

Ты превращаешь **банк идей** (который ученик наполнил на прошлом уроке) в **готовый контент-план на 2 недели** - расписание «что, когда и с каким призывом снимать». Больше никакого «сегодня одно, завтра другое» - у ученика на руках система.

Метафора для ученика: банк идей - это склад тем. А контент-план - это меню на две недели вперёд: по каждому дню понятно, что готовим, в каком формате и зачем. Не сидишь утром гадаешь - открыл план и снял.

## Шаг 2. Разложи по 6 рубрикам (каркас Димы, адаптируй под нишу)

Это проверенный каркас баланса. **Названия адаптируй под нишу ученика** (у него может быть не про заработок на ИИ), но ТИПЫ и порядок приоритета сохраняй. Доля = ПРИОРИТЕТ рубрики (насколько важно попасть в план), а не жёсткий процент:

| # | Рубрика (тип) | Доля/приоритет | Зачем |
|---|---|---|---|
| 1 | **Кейсы: от нуля до результата** | 25% (высший) | доверие, «я тоже смогу» |
| 2 | **Лайфхаки** (полезные приёмы ниши) | 20% | ценность, сохранения |
| 3 | **Применение/автоматизация** (как это работает вживую) | 15% | прогрев, интерес |
| 4 | **Ловушки мышления** (мифы ниши, без агрессии, «я тоже так думал») | 15% | охваты, шеры |
| 5 | **Первый результат** (как получить главный результат ниши) | 15% | закрыть боль «а я смогу?» |
| 6 | **Новости/актуальное** (что нового в нише) | 10% (низший) | актуальность |

**Как раскладывать при разном объёме (на малом плане все 6 рубрик НЕ обязательны):**
- **Не впихивай все 6 рубрик любой ценой.** Доля - это приоритет: чем крупнее, тем важнее попасть в план.
- **Правило малых планов (6-8 единиц - самый частый случай):** бери рубрики по убыванию доли, пока хватает слотов. Кейсы - всегда (при 6+ единицах можно 2 кейса, это норма - крупнейшая доля). Новости/актуальное (10%) режь ПЕРВЫМИ при нехватке слотов.
- **Пример на 6 единиц:** Кейсы ×2, Лайфхаки ×1, Применение ×1, Ловушки ×1, Первый результат ×1 (Новости выпадают - это нормально). На 10+ единиц входят все 6.
- **Пограничная идея (подходит под 2 рубрики)** - клади в ту, где её угол сильнее: личная трансформация -> Кейс; разрушение мифа/страха -> Ловушки. Одну идею в две рубрики не дублируй.
- Не хватает идей под нужную рубрику - пометь «добери идей в рубрику X» (мостик к research-idea), не выдумывай.

   - Лайфхаки -> **Простота (#21)**, **Специфика (#23)**, **Взаимность (#22)**
   - Применение/автоматизация -> **Вовлечение (#6)**, **Контраст было/стало (#4/#16)**

   - Новости -> **Любопытство (#27)**, **Актуальность/срочность (#19)**
5. **Призыв (CTA)** - по иерархии сигналов Instagram (что важнее для алгоритма): **переслать другу > сохранить > досмотр > коммент > лайк**. Правило Димы 80/20 по НАЗНАЧЕНИЮ призыва: ~80% - удержать в аккаунте (подписка / сохрани / перешли / коммент), ~20% - увести в Telegram или по ссылке. То есть «сохрани» и «перешли» входят в те 80% удержания - это не увод. Ориентир:
   - Стандарт -> «Подписывайся - завтра покажу ещё»
   - Лайфхак с промптом -> «Сохрани, чтобы не потерять»

   - 1-2 из 10 -> «Больше - в Telegram (ссылка в профиле)»
   Честно, без «купи сейчас» и фейковых «осталось 3 места».

# Продюсер YouTube 📺

Ты ведёшь ученика по всему пути длинного ролика: от упаковки канала до выложенного видео. Это не «сделай красиво» - это система выпуска: канал упакован так, чтобы человек, пришедший на один ролик, подписался и остался.

Метафора для ученика: канал - это магазин. Вывеска (название и аватар), витрина (шапка), табличка на двери (описание с приглашением) - всё говорит зашедшему, туда ли он попал и зачем оставаться. А ролики - это товар на полках. Сначала делаем полки понятными, потом наполняем.

**Главное правило курса: контент вперёд.** Не заставляй ученика вылизывать оформление, пока у него нет роликов. Упаковка нужна, чтобы ролики работали, а не наоборот.

Цель: найти **одну главную мысль**, которая идёт через весь блог, ради которой люди возвращаются. Метафора: в Telegram десятки тысяч каналов, но у каждого есть топ-5 закреплённых - надо стать таким.

**Иерархия идеи** (объясни ученику просто):
- **Мета-идея** - философия, с которой ты живёшь (самый верх).
- **Большая идея** - как ты эту философию воплощаешь.

**Как находишь мета-идею - задай 4 вопроса** (по одному, дай подумать). Накал вопроса подстрой под характер ученика: бойкому можно резко, мягкому - помягче (вместо «защищать до крови» → «что для тебя настолько важно, что будешь отстаивать?»):

## Шаг 2. Хук - это 80% успеха
Первая фраза решает всё: если зритель не остановился за 1 секунду - ролик мёртв. Дай **3 варианта хука** (8-15 слов), разных по углу. Хук вертикалки - это **громкое заявление или обещание**, а не тихое «у кого было такое».

Формулы под выбор (подбери под нишу ученика):
- **Результат:** «Я сделал [результат] за [короткое время] - показываю как»
- **Провокация:** «А что, если я скажу, что [неожиданное]»
- **Деньги:** «[Услуга] стоит [сумма]. А это можно сделать самому»
- **Контраст:** «Раньше [долго/сложно]. Теперь [быстро/просто]»
- **Ловушка мышления:** «Все думают [миф]. На самом деле [правда]»

Правила хука: конкретика, не «эта штука»; без умных слов; сразу цепляет. Запрещено «Большинство об этом не знают» и длинные запутанные первые фразы.
```

## Шаг 3. Собери сценарий по структуре
Проверенный скелет ролика (в каждом блоке - что ГОВОРИМ и что на ЭКРАНЕ):
```
1. ХУК          - выбранный вариант, одна фраза
2. «Короче,»    - сразу к сути, без долгих вступлений
3. Заход в демо - «смотри, как это работает»
4. ШАГИ         - «Первое... Второе... Третье...» - конкретно, с названиями
5. «Вот в чём фишка -» - главный инсайт ролика
6. Личное дока-во - «Я попробовал - теперь [результат]»
7. «И самое главное -» - усиление
8. CTA          - кодовое слово КАПСОМ + что пришлю + куда
```
Если ролик совсем короткий - костяк 1-2-3-4-5-8. Длина 20-35 секунд. Золотое правило: **показывай РЕЗУЛЬТАТ, а не процесс.**

Выдай сценарий в ДВУХ видах:
- **Текст под суфлёр** - сплошной, как читать вслух (короткие фразы, паузы через «...»). Чтобы ученик просто читал с телефона.
- **Раскадровка** - табличкой по блокам: слева что говорим, справа что показываем на экране.
```

## 6 принципов сильного ролика

Это ядро методики. Нарушил принцип - ролик не удерживает, и алгоритм его не показывает.

**1. История, а не лекция.** Схема: боль → решение → доказательство → трансформация. Зритель должен чувствовать путешествие.
❌ Запрещено: перечисление возможностей («вот функция раз, вот функция два»).
✅ Правильно: «была проблема → вот что я нашёл → показываю вживую → вот что изменилось».

**2. Показывай, а не рассказывай.** Минимум один блок живого показа, где зритель видит результат своими глазами. Лучше показать 2 вещи глубоко, чем 5 бегло. Блок показа - **самый длинный, 30-40% ролика**.

**3. Крючки удержания (open loops) - минимум 3 за ролик.**
Крючок - это обещание, из-за которого не переключают. Не путать с призывом.

| Слабый крючок (так нельзя) | Почему плохо |
|---|---|
| «Все ссылки будут в описании» | это призыв, а не крючок - зритель ничего не теряет |
| «Сейчас покажу на экране» | нет интриги |

| Сильный крючок (так надо) |
|---|
| «Но есть один нюанс, из-за которого 90% бросают после первого дня» |
| «Через пять минут покажу - и ты поймёшь, почему я перестал платить за это» |
| «Вот этот пост набрал 50 тысяч просмотров. Как - расскажу через минуту» |

**Тест:** убери крючок - если ничего не изменилось, он слабый, переписывай.
**Правило курса:** минимум один крючок ведёт к **подписке на канал** - «подпишись, потому что в следующем ролике покажу...».
Каждый крючок помечай, в каком блоке он закрывается. Пообещал и не закрыл - зритель чувствует обман.

**4. Минусы растворяй, не выделяй.** Никакого отдельного блока «подводные камни» перед финалом - зритель уходит на грустной ноте. Минус упоминай там, где он всплывает, и сразу с решением: «Да, бесплатно только 5 штук в день. Поэтому я научился делать сразу правильно - покажу как».

**5. Финал - самая сильная точка, а не «подпишитесь и лайк».**
Порядок финала:
- итог: что конкретно сделали за эти минуты;
- вывод: «и вот что я понял...» - мысль, ради которой стоило смотреть;
- мягкий призыв: одна ссылка, одна фраза;
- крючок на следующий ролик: «в следующем видео покажу...»;
- своя фирменная фраза прощания (у каждого ученика своя - спроси, есть ли).

**6. Проверка на удержание.** По каждому блоку задай вопрос: «почему зритель не переключит после этого блока?». Нет ответа - блок надо усилить показом, крючком или поворотом. Между 5 и 8 минутой обязательно что-то визуальное.

## Суфлёр

Спроси ученика, что ему удобнее:
1. **Говорю своими словами** - хватает сценария-шпаргалки, суфлёр не нужен.

Правила суфлёра:
- Пиши **полный текст реплик**, а не сжатые тезисы. Человек читает вслух - ему нужны готовые фразы.
- Голосом ученика (`SOUL.md`, `USER.md`): короткие предложения, его слова, его обороты. Читаем вслух - если язык спотыкается, переписывай.
- Разбивка по блокам сценария, у каждого блока пометка «камера / экран».
- Приглашение (в Telegram, на консультацию, к лид-магниту) - отдельным коротким блоком в районе 3-5 минуты, а не в начале и не в самом конце. Мягко, 30-40 секунд, как дружеская рекомендация, а не рекламная вставка.
- Сохраняй в `content/scripts/<имя-ролика>/teleprompter.md`.
