## Sources (source-hierarchy level per METHODOLOGY.md)

- **Claude Code — Create custom subagents** (`https://code.claude.com/docs/en/sub-agents`) — official docs, fetched directly in full. Level 2. Key quotes: "the only channel from parent to subagent is the prompt string that the main agent writes when it delegates"; "The parent receives the subagent's final message verbatim as the Agent tool result"; "Each subagent invocation creates a new instance with fresh context. To continue an existing subagent's work instead of starting over, ask Claude to resume it. Resumed subagents retain their full conversation history, including all previous tool calls, results, and reasoning. The subagent picks up exactly where it stopped rather than starting fresh"; "Claude uses the `SendMessage` tool with the agent's ID or name as the `to` field to resume it... - **Claude Code — Orchestrate teams of Claude Code sessions** (`https://code.claude.com/docs/en/agent-teams`) — official docs, fetched directly in full. Level 2. Key quotes: `TeammateIdle` — "runs when a teammate is about to go idle. Exit with code 2 to send feedback and keep the teammate working"; `TaskCompleted` — "runs when a task is being marked complete. Exit with code 2 to prevent completion and send feedback"; "Unlike subagents, which run within a single session and can only report back to the main agent, you can also interact with individual teammates directly."
- **Claude Code — Message your other Claude Code sessions (cross-session messaging)** (`https://code.claude.com/docs/en/cross-session-messaging`) — official docs, fetched directly in full. Level 2. - **Anthropic — How we built our multi-agent research system** (`https://www.anthropic.com/engineering/multi-agent-research-system`) — official engineering blog, fetched directly. Level 2 (official post about own production system; distinguish from a marketing announcement — this describes internal architecture and named failure modes, including ones that reflect poorly on the system, which weighs against pure marketing framing). Key findings, fetched and asked directly about the five brief questions: task contract = "objective, an output format, guidance on the tools and sources to use, and clear task boundaries"; named early failure = vague short instructions ("research the semiconductor shortage") caused misinterpretation; result return = "a list of companies" style compiled output back to the lead; sufficiency = "the lead agent synthesizes these results and decides whether more research is needed" — **no rubric named in the fetched material**; refinement = "if so, it can create additional subagents or refine its strategy" — **spawns new subagents, does not resume an existing one**; named coordination failures = duplicated work between subagents on overlapping scope, up to 50 subagents spawned for simple queries before capping.

- **Microsoft AutoGen — AgentChat Swarm / HandoffMessage** (`microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/swarm.html`, `.../dev/_modules/autogen_agentchat/teams/_group_chat/_swarm_group_chat.html`, `.../dev/_sources/.../swarm.ipynb.txt`) — official docs + source module + worked example, all three fetched directly, 2026-08-12 follow-up closing a gap the coordinator flagged in this file's first pass. Level 1-2 (source module is a primary artifact). Speaker-selection code: `for message in reversed(thread): if isinstance(message, HandoffMessage): self._current_speaker = message.target`; absent a handoff, `return self._current_speaker` — same agent keeps the turn. **Confirmed: baton-pass, no automatic return** — "There is no automatic mechanism for control to return to a previously handoff-ing agent... No code path automatically reverts to an earlier speaker." Voluntary return happens only because a given agent's own system prompt says so (worked example: `financial_analyst`'s prompt — "Always handoff back to planner when analysis is complete" — executed as an ordinary `transfer_to_planner()` tool call, mechanically identical to any other handoff). **Confirmed gap**: no refinement/corrective-follow-up example found in the fetched notebook source — every handoff shown is forward delegation or a completion handoff, none narrows or corrects prior specialist work. Termination is a separate primitive (`HandoffTermination(target="user") | TextMentionTermination("TERMINATE")`), not coupled to handoff logic.
