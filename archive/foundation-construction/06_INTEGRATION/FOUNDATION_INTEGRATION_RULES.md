# FOUNDATION_INTEGRATION_RULES.md

Правила отбора для этапа между «нашли находку» и «внесли в Foundation». Не свойство Foundation (это продукт) и не метод извлечения знаний (это `skills/reverse-engineering/`) — правила решения, что делать с уже извлечённым.

---

## Принцип 1

Не создавать новую сущность, если существующую можно усилить.

## Принцип 2

Новая сущность появляется только тогда, когда ни один существующий файл не может вместить механизм без нарушения своей собственной ответственности (файл начал бы отвечать за что-то, что не является его задачей).

## Принцип 3

Каждая находка после исследования обязана получить ровно один статус:

- **Подтверждение** — механизм, который у Foundation уже есть; находка просто добавляет независимый источник.
- **Усиление существующего** — механизма у Foundation нет, но он умещается внутрь уже существующего файла, не меняя его ответственность.
- **Новый механизм** — ни один существующий файл не может его вместить; создание новой сущности оправдано.
- **Не переносится** — специализация, дубликат другого источника, отклонено ранее, вне охвата, либо материал с ограничением на использование (авторское право).

Без одного из этих четырёх статусов находка не считается обработанной — только собранной.

---

## Зачем это отдельно от reverse-engineering

`skills/reverse-engineering/` отвечает на вопрос «как честно извлечь механизм из источника». Эти правила отвечают на другой вопрос — «что делать с уже извлечённым механизмом, чтобы Дом не раздувался». Первое — метод исследования. Второе — дисциплина архитектора, которая начинается только после того, как исследование закончено.
