# Взаимодействие

## Два разных протокола, не один

- **Агент ↔ инструмент** — покрыто механизмом `skills/`: агент вызывает способность, способность выполняется, результат возвращается.
- **Агент ↔ другой агент** — Engineer ↔ Researcher: физический канал проверен реальными прогонами. Постоянный протокол взаимодействия — `Proposal`, источник статуса: `ENGINEER/DECISIONS.md`. Другие пары — не покрыто автоматически.

## Engineer ↔ Researcher — как это работает по факту

Engineer может напрямую поставить исследовательскую задачу, без владельца как реле. Проверено дважды реальным прогоном 2026-08-12 (включая закрытие Researcher собственного пробела по её же уточнению).

- **Вход** — узкий research brief с критерием достаточности, зафиксированным до поиска, в формате `MISSION.md`/её собственного `OPEN_QUESTIONS.md`.
- **Кто решает «достаточно»** — Engineer, не Researcher, по зафиксированному критерию.
- **Уточнение** — Engineer может обратиться повторно к тому же вызову с конкретным пробелом («по X недостаточно») — не с нуля.
- **Что остаётся здесь** — находки Researcher пишет в свои собственные файлы (`knowledge/`, `memory/`, свой `OPEN_QUESTIONS.md`) по собственным правилам роста знания (`MISSION.md`, «Knowledge Growth») — не в формат Engineer.

Полная запись решения и обоснование — `ENGINEER/DECISIONS.md`, 2026-08-12.
