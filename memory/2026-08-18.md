Три под-вопроса, все закрыты с запасом по зафиксированному критерию (минимум 2 системы на уровне механизма + источник, честное «не найдено» там, где нечего сказать):

**Sandboxing** — Claude Code (шесть слоёв изоляции: встроенный Bash-сэндбокс, beta `sandbox-runtime`, dev container с default-deny iptables firewall, custom container, VM, Anthropic-hosted web VM — все с официального `code.claude.com`, полный fetch) и OpenAI Codex CLI (Seatbelt/Landlock+seccomp, песочница включена по умолчанию без Docker вообще — противоположный дизайн-выбор относительно Claude Code, официальный `learn.chatgpt.com`, полный fetch). Честно найденный пробел: встроенный Bash-сэндбокс и `sandbox-runtime` **официально не поддерживают нативный Windows** — прямо релевантно среде владельца.

**Non-interactive-конфигурация, и что технически заменяет approval** (ядро брифа, не просто «какой флаг выключает проверку») — три системы, все явно называют механизм замены: Claude Code `auto`-режим — отдельная модель-классификатор ревьюит каждое действие вместо человека, с версионированным растущим списком безусловных блокировок, получает только сообщения/tool calls/CLAUDE.md (результаты инструментов вырезаны — защита от prompt injection на уровне архитектуры); OpenAI Codex — явно названные две независимые оси (`sandbox_mode` — что технически возможно, `approval_policy` — когда спросить), `approval_policy=never` безопасен именно потому, что `sandbox_mode` держит техническую границу независимо от политики; AutoGen — честный контрастный случай: `human_input_mode="NEVER"` сам по себе ничем не защищён, единственная граница безопасности — выбор Docker-executor вместо локального, никакого классификатора или двухслойной политики нет вообще (документация Microsoft сама предупреждает про локальный executor).

**Post-hoc audit trail** — GitHub Copilot coding agent (подписанные коммиты + постоянная ссылка от каждого коммита на session log + структурный запрет: инициатор задачи технически не может одобрить получившийся PR — превращает лог из опции в обязательный gate) и AWS Bedrock AgentCore (каждый вызов агента логируется в CloudTrail на уровне платформы, не самим агентом — требует AWS-инфраструктуры, которой у нас нет). Дополнительно, новая деталь того же Claude Code (не переоткрывает закрытый 2026-08-12 вопрос про execution record — тот отвечал «можно ли получить лог», этот — «проверяет ли что-то результат само»): классификатор делает отдельную проверку **после** завершения саб-агента, полной истории его действий, и помечает результат «unreviewed and should be treated as untrusted», если сама проверка не прошла технически.

Применимость к среде владельца явно названа по каждой находке, не обобщена: `auto`/`dontAsk`-режимы Claude Code — уже доступны сегодня без новой инфраструктуры (план владельца — Pro/Max/Team/Enterprise — не проверен, честно [UNKNOWN]); паттерн «исполнитель ≠ одобряющий» у GitHub Copilot — независимое внешнее подтверждение уже используемой вручную сегодня практики Engineer (`ENGINEER/DECISIONS.md`, prepare+commit Engineer / push владелец); контейнеризация — физически возможна на Windows через Docker Desktop, но не настроена ни у одного из трёх репозиториев-агентов — назван как пробел, не закрыт этим исследованием.
